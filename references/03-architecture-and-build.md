# 架构与候选生成

## 职责

把用户确认的范围、规则、证据、资料建议、脚本候选与权限边界转成最小充分的候选 Skill；在准确路径和写入范围获授权后生成候选文件并完成静态检查。

不正式安装，不建立发现入口，不做业务验证或激活。

## 输入与环境

接收已确认任务、候选规则与证据、资料与外部来源、脚本或资源候选、权限停止条件、目标消费者和兼容边界。

未知与冲突不能默默补齐，必要时返回证据阶段。

先由现有配置和任务范围核实目标环境。只有无法确定且会影响实现或权限的差异才询问；常规选择沿用当前消费者和管理约定。

## 候选架构蓝图

创建文件前先提出与风险相称的蓝图。让用户看清：

- 解决和不解决什么；
- 范围与结构理由；
- 候选名称、触发与边界；
- 输入、输出与验收；
- SKILL.md、references、assets、scripts 或外部资料的分配；
- 默认回答的长度与信息密度、需要用户做出的决定，以及哪些详细证据进入项目记录；
- 目标环境、依赖与兼容范围；
- 文件变更、候选路径、冲突与回退；
- 静态和行为测试思路。

用户已要求创建或优化时，简述必要结构与影响后直接实施；不为名称、文件拆分等常规设计重新索权。

## 名称与 description

机器名简短、面向动作或能力，符合目标环境命名规范，并与文件夹身份一致。

description 是派单规则。按误触发风险决定是否写实际能力、真实触发表达、适用与排除场景、相邻 Skill 边界；不写宣传语，也不为形式机械写长。

发现同名对象先判断是否就是用户要求更新的本体；是则原位修改，另一个对象且归属不清时才暂停相关写入。

## SKILL.md

只写会改变执行结果的非显而易见内容。开放任务保留合理判断空间；事实、权限、敏感资料、外部写入、不可逆操作、固定算法与脆弱流程按风险提高具体程度。

按需表达职责边界、输入、流程或判断、输出合同、资料或脚本路由、权限、人工确认、失败与停止条件；不要求固定标题。

## 交互与输出成本

把可读性视为架构质量的一部分。默认先交付结论、关键依据、未知项和下一步决定；不要为了展示完整而强制输出所有可选字段、技术台账或重复的权限声明。

评估一次调用需要用户阅读多少内容、做多少决定、是否重复询问已有信息，以及详细证据能否留在项目记录而不妨碍用户理解主结果。高风险或需要逐项审核时可以增加细节，但要说明原因。

## 渐进披露与单一事实源

SKILL.md 保留每次调用所需规则和路由，条件细节放支持文件并写明读取条件。不要每次加载全部资料。

同一事实或规则只维护一个权威位置；SKILL.md 说明何时读取，references 或外部资料维护事实本身。

## 配套资源

- references：规则、政策、事实、案例、样本、字段、输出规范和条件流程；
- assets：直接进入最终产物的模板、图片、字体、图标或项目骨架；
- scripts：唯一、重复、易漏且程序更可靠的计算、转换和检查；
- agents/openai.yaml：仅在 Codex 需要 UI 元数据或策略时考虑；
- 外部资料源：继续引用权威知识库，但处理路径、权限、可移植性和缺失行为。

简单 Skill 不创建空目录。模板供 AI 阅读时倾向 references，直接进入产物时倾向 assets。

## 多消费者

选择共享核心、核心加环境适配或单环境支持。不能因一个消费者成功就声称多端兼容；明确已验证范围。

## 写入计划

展示候选路径、存在状态、将新建和修改的文件、重叠对象、明确不动对象与回退方式。路径由当前管理规则决定，不硬编码；不确定时询问。

执行请求覆盖目标范围内的生成、静态检查及必要本地修正，不要求用户枚举每个阶段和准确文件。新的业务范围、全局安装、入口、激活或外部操作仍需核对是否已有对应授权。

## 生成候选

只创建蓝图中有用途的文件：

- 不残留模板说明、占位符或未替换字段；
- 不编造无证据规则；
- 不把设计讨论和测试报告塞进运行文件；
- 不把个人绝对路径写进分享版；
- 不默认创建 README、安装教程或发布材料；
- 不修改相邻 Skill、清单或入口。

明确优化现有 Skill 时读取原文并保留恢复依据后原位修改。只有探索替代、并存比较或兼容试验时才建立候选副本。

## 静态检查

按环境检查 frontmatter、name 与文件夹身份、description 区分度、相对链接、资源引用、占位符、绝对路径、敏感信息、脚本执行和结构一致性。

结构校验不证明业务效果。

## 输出与门禁

按复杂度交付候选文件夹、蓝图、构建记录、静态结果、兼容范围、未解决问题和行为测试计划中的最小充分集合。

只报告候选与静态状态，不声称稳定可用、双端兼容或正式激活。

完成当前目标所需的检查后交付实际结果与验证边界；重要行为尚需验证且在已授权范围内时继续验证。不要机械提出下一阶段或强迫用户选择安装。外部操作确实缺授权时，再给出具体可审查内容和一次必要请求。
