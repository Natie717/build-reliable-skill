# 立项与现有能力分诊

## 职责

只读判断目标是否值得沉淀、是否已有现成能力，以及更适合直接协作、临时指令、脚本、Skill、工作流还是 Agent。

本阶段不采访全部经验，不创建文件，不安装或改造现有能力。

## 先理解真实目标

优先使用已有上下文。按需要确认：

- 用户想解决的真实问题与期待结果；
- 当前是一次性需求还是重复任务；
- 现在的做法和主要困难；
- 目标是实际使用、内部沉淀、学习练习还是对外分享；
- 即使存在类似能力，用户是否仍有独立维护或个性化目的。

可以指出重复建设风险，但不能仅因发现类似 Skill 就否定用户目标。

## 只读检查现有能力

按实际环境由近到远检查：

1. 当前模型和工具原生能力；
2. 当前已安装或可调用 Skill；
3. 用户 Skill 清单、Manifest、总账与项目资产；
4. 当前能力不足时的外部候选。

先用名称与 description 轻量筛选，只对可能匹配的候选读取完整 SKILL.md 和相关资源。

按需核对：

- 实际职责、触发和排除条件；
- 输入输出；
- references、assets、scripts 与依赖；
- 权限和停止条件；
- 目标工具与作用域；
- 来源、作者、维护状态与 License；
- 在目标环境是否有真实验证证据。

外部搜索结果标记为候选；不自动下载、安装或修改环境。

## 适合 Skill 的判断维度

综合判断，不做固定打分或机械问卷：

- 重复性：约三次只是提醒，不是门槛；
- 稳定性：是否已有相对稳定的流程、规则或判断；
- 非显而易见性：是否增加模型原本不知道的经验、资料、标准或边界；
- 可验证性：输入、输出与成功失败能否观察；
- 证据：是否有真实任务、样本、案例或资料；
- 状态复杂度：是否需要跨天状态、复杂分支、重试、监听、队列或多人审批；
- 风险权限：是否涉及删除、发布、发送、付款、覆盖或敏感资料。

已有上下文能够回答的内容不要重复询问。

## 推荐形态

按实际情况建议：

- 直接协作：一次性、方法尚不稳定或只需完成当前任务；
- 临时指令：简单规则和短期试验；
- Script 或工具：输入输出确定、结果唯一、需要稳定重复；
- Skill：有可复用流程、判断、资料或边界，不需要长期自主状态；
- 工作流：多个固定步骤和产物按顺序交接；
- Agent：持续职责、复杂分支、状态、重试、审批或多能力调度；
- Agent＋Skills：Agent 管理状态和调度，Skills 提供岗位方法。

说明推荐理由，以及为什么不选择相邻形态。

## 与现有 Skill 的关系

可以建议：

- 直接使用现有 Skill；
- 改造候选副本；
- 组合现有能力并判断简单串联、工作流或 Agent；
- 新建 Skill；
- 暂时先完成真实任务积累证据。

说明匹配点、差距、兼容性和待验证边界。不直接调用、安装、修改、覆盖、合并或删除。

## 输出与门禁

用适合当前复杂度的形式说明：

- 目标理解；
- 检查过的能力与候选；
- 推荐形态和理由；
- 能力差距与证据缺口；
- 风险和权限；
- 建议下一步与需要用户决定的内容。

区分事实、证据判断、未核验候选和未知项。

然后停下来，让用户选择使用现有能力、改造、新建、先实践、改做其他形态或停止。未经确认，不进入证据提取，不创建文件。
